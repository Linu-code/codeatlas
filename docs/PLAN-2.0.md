### 1.0 硬性限制（后续版本的主要突破点）

| 维度 | 1.0 限制 |
|---|---|
| **语言** | 仅 JavaScript / TypeScript / TSX / Python |
| **规模** | 单次分析 ≤ 400 文件、单文件 ≤ 256 KB |
| **调用图** | > 60 节点按连接度截断为骨架图 |
| **数据源** | 仅 GitHub 在线 + `.zip`；**不支持文件夹拖入 / 本地目录 / 本地 Git 仓库 / GitLab / Gitee** |
| **持久化** | 只缓存原始文件内容；**分析结果（符号索引/度量/图）每次重算** |
| **平台** | 仅 Windows（exe + NSIS）→ 2.1 解决 |

## 2. 2.0 定位

> **一句话**：从「能读懂一个仓库的浏览器」升级为「能处理真实工程规模的**本地代码理解工作台**」。

四条主线：

- **广度** —— 支持更多语言 + 更多数据源（本地优先，摆脱"必须联网 + 必须打包成 zip"）。
- **深度** —— 从函数级调用图，升级到**模块依赖 / 类继承 / 架构分层**级视图，并把分析结果持久化。
- **落地** —— 补齐"阅读路线"、命令面板等生产力功能。
- **工程** —— 补齐 E2E、可访问性、依赖升级，为 2.1 多平台打好基础。

> **AI 边界（全局定调）**：红线不变——**不接入任何在线 AI / 云端 LLM、不上传任何代码与数据**。
> 唯一例外是 2.2 的**本机 Ollama 回环调用**（`127.0.0.1:11434`）：模型与推理全在用户自己机器上，无任何外发流量。未安装 Ollama 时，全部确定性分析功能照常工作，AI 入口自动隐藏。

## 3. 2.0 里程碑（N1–N6）

> 编号用 `N`（Next）以区别 1.0 的 `M`。每项给出：内容 / 动机 / 依赖 / 验收要点。

### N1 · 语言与分析规模扩容
- **内容**
  - 新增 tree-sitter 语法包：**Rust、Go、Java、C/C++（先 C，后 C++）、C#**，接入现有 `analysis/parser.ts` 解析器池（扩展点已预留）。
  - 上限提升：文件数 400 → **2000**、单文件 256 KB → 1 MB（可配置）。
  - 调用图截断阈值提高 + 提供"全图 / 骨架图"切换。
- **动机**：工具最直接的扩容——覆盖后端/系统语言才有真实使用场景。
- **依赖**：tree-sitter 语法包 ABI 必须与 `web-tree-sitter` 匹配（见 PLAN.md「升级路径」，需成对升级 + `npm run check:tree-sitter` 自检）。
- **验收**：5 种新语言各有真实 AST 单测（符号/调用/度量数值断言）；`check:tree-sitter` 覆盖全部语法包。

### N2 · 阅读路线 + 命令面板（补齐定位 gap）
- **内容**
  - **阅读路线**：基于 `pagerank.ts` 依赖图 + 目录分层，自动生成"**建议阅读顺序**"（入口 → 核心枢纽 → 边缘），在文件树上以序号/高亮呈现，并可一键写入 AI 上下文包。
  - **命令面板**：`Ctrl/Cmd+K` 模糊搜索（文件 / 符号 / 命令统一入口）。
  - **符号搜索**：`Ctrl/Cmd+T` 直接跳到符号定义（复用 `scopeGraph.ts`）。
  - **大纲视图**：当前文件的符号树（函数/类/方法）。
- **动机**：补上宣传 gap，并把已有分析能力转化为"导航"这一核心价值。
- **依赖**：无强依赖，可与 N1 并行。
- **验收**：阅读路线顺序有确定性单测；命令面板/符号搜索有 E2E。

### N3 · 架构视图（深度分析）
- **内容**
  - **模块依赖图**：文件 & 目录级 `import/use` 图（比函数调用图更高层），支持 Mermaid 导出。
  - **循环依赖检测**：强连通分量（Tarjan）标记 + 面板告警。
  - **类图 / 继承·接口关系**：面向 OOP 语言，类/接口/继承/实现关系图。
  - **分层视图**：按目录用途规则（`directories.ts`）聚类，展示模块边界。
- **动机**：调用图只解决"函数之间"，真实理解项目需要"模块之间"。
- **依赖**：N1（多语言 AST）。
- **验收**：构造 fixture 断言依赖边/环检测结果/继承关系；E2E 断言图渲染。

### N4 · 分析结果持久化 + 增量分析
- **内容**
  - 把符号索引、度量、依赖图缓存进 IndexedDB（按 `repo@commit` 版本化，沿用 `cache.ts` 的 `TREE_FORMAT_VERSION` 模式防止旧快照误导）。
  - **增量分析**：仅重解析变更文件，未变文件复用缓存。
- **动机**：解决"每次打开都全量重算"，大仓库体验质变。
- **依赖**：N1（规模提升后更迫切）。
- **验收**：缓存命中时二次打开分析耗时显著下降；版本不匹配自动失效。

### N5 · 导出与工作区
- **内容**
  - **报告导出**：单文件 HTML（架构概览 + 度量 + 图 + 阅读路线），可直接分享。
  - **多项目工作区**：同时打开多个仓库，标签切换（窗口内 tab 化，而非每项目一个系统窗口）。
  - **本地目录 / 本地 Git 仓库数据源**：直接打开本地文件夹或 `git` 工作区（Tauri 已有 fs 能力），彻底摆脱"必须先打包 zip"。
- **动机**：从"单仓库查看器"变成"工作台"。
- **依赖**：无（数据源部分可与 N1 并行）。
- **验收**：导出报告可离线打开且内容完整；本地目录加载有 E2E 或人工验证。

### N6 · 质量与工程债（2.0 收口）
- **内容**
  - **依赖升级**：`web-tree-sitter` 0.22 → 0.25+ 新版 ABI 迁移（与语法包成对升级）。
  - **E2E 补全**：在线场景（GitHub 请求打桩）、桌面端自动化（Tauri WebDriver）。
  - **可访问性**：键盘全导航、ARIA、对比度校验。
  - **版本号规范化**：`package.json` / `Cargo.toml` / `tauri.conf.json` / CI 模板对齐 ✅（2026-09-17 已完成）。
- **动机**：还债，并为 2.1 多平台打包扫清障碍。
- **依赖**：ABI 升级需在 N1 之后、其他里程碑之前解决。
- **验收**：CI 全绿；依赖升级后 `npm test` + `npm run check:tree-sitter` 全通过。
- **注**：多平台打包已拆出独立为 2.1，见第 4 节。

## 4. 2.1 规划 · 多平台支持

> 由原 N6 的"多平台打包"拆分独立成版。**2.0 之后先把 Windows 之外的平台补齐，扩大分发面。**

- **内容**
  - **macOS 打包**：`.dmg` + `.app`（universal binary：x64 + Apple Silicon）。
  - **Linux 打包**：`.deb` + `.AppImage`。
  - **CI 构建矩阵**：`.github/workflows/release.yml` 改为 `windows-latest` / `macos-latest` / `ubuntu-latest` 三平台矩阵，打 tag 即自动产出三平台安装包并发布 Release。
  - **平台适配**：路径处理统一（`/` vs `\`）、快捷键 `Cmd` / `Ctrl` 分支、文件关联（macOS `.app` / Linux `.desktop`）、系统主题跟随在各平台验证。
  - **签名与公证**（可选）：macOS 需 Developer ID 签名 + 公证才能在 Gatekeeper 下顺畅运行；无签名则文档说明"右键打开"。
- **动机**：Windows-only 严重限制受众；Tauri 本身跨平台，成本主要在多平台 CI 与打包配置。
- **依赖**：2.0 完成（依赖 N6 的依赖升级与质量债清理）。
- **验收**：三平台产物均可启动、可打开本地 ZIP/目录；CI 矩阵全绿；Release 页含三平台包。
- **风险**：macOS 签名/公证需 Apple 开发者账号（$99/年）；Linux 发行版碎片化。应对：先发未签名版 + 文档说明。

## 5. 2.2 规划 · 可选本地 AI 助手（Ollama）〔纯本地方案，默认关闭〕

> 由原 N7 独立成版。**可选的增强项，不是必需依赖**——没有 Ollama 的用户体验与 1.0 完全一致。

- **红线（不可逾越）**
  - 只调用 `http://127.0.0.1:11434`（Ollama 默认回环地址）；**网络白名单新增且仅新增这一条本地地址**，其余外部域名仍然全禁。
  - 默认**关闭**；启用前需用户在设置页显式勾选并确认"仅调用本机服务"。
  - 不发送遥测；prompt 与模型输出**不落盘**（除用户主动导出）；代码内容仅在内存中传给本地模型。
  - 所有 AI 输出**明确标注**"由本地模型生成，可能存在错误"，与确定性分析结果区隔。
- **能力方向（轻量化，从低风险到高价值排序）**
  1. **文件/函数摘要**：对选中文件或模块生成一句话"它在做什么"，补充现有模板规则（`directories.ts`）。
  2. **自然语言导航**：把提问转成结构化检索（"哪里调用了 `renderTree`"→ 调用 `scopeGraph` / `search.worker` 后解释结果），**先检索再解释**，减少幻觉。
  3. **仓库问答（RAG-lite）**：以现有**结构化分析结果**（符号索引 + 调用图 + 度量）为上下文，而非全文塞入，控制 token 与显存占用。
  4. **阅读路线解说**：结合 N2 的阅读顺序，用自然语言解释"该先看哪个文件、为什么"。
  5. **上下文包精炼**：用本地模型对 `contextPack.ts` 的输出做压缩/改写（可选）。
- **技术要点**
  - 接口：Ollama HTTP API（`/api/chat`、`/api/generate`、`/api/embeddings`），NDJSON 流式输出。
  - 模型：由用户自选，推荐轻量代码模型（如 `qwen2.5-coder:1.5b/7b`、`llama3.2:3b` 等）；UI 内提供"检测已安装模型"列表。
  - 可用性探测：启动时 ping `11434`，失败即隐藏全部 AI 入口（零报错、零阻塞）。
  - 降级：**Ollama 不可用 / 模型不存在 / 超时 → 自动回落到确定性结果**，绝不阻断核心功能。
  - 与现有能力的关系：**AI 上下文包（导出给外部 AI）保持不变**；本项是"内置一个本地消费端"，两者互补。
- **动机**：满足"想用 AI 但坚决不上云"的用户；强化"纯本地"这一差异化卖点，而非削弱它。
- **依赖**：N4（结构化结果持久化，作为 RAG 上下文）；建议 2.1 完成后再做。
- **验收**：无 Ollama 时全部功能与 1.0 一样（回归测试保证）；有 Ollama 时能完成文件摘要与仓库问答，且**断网状态下可用**；网络白名单测试需断言"仅放行 127.0.0.1:11434"。
- **风险**：模型输出不可靠、显存/内存占用、prompt 注入（对本地模型影响有限）。应对：默认关闭 + 强标注 + 只做"检索后解释"而非自由生成。

## 6. 优先级建议

| 优先级 | 内容 | 理由 |
|---|---|---|
| **P0** | N1（语言/规模）、N5 的数据源部分（本地目录） | 直接扩大适用场景，投入产出比最高 |
| **P1** | N2（阅读路线/命令面板）、N4（持久化/增量） | 补齐定位 gap + 解决体验瓶颈 |
| **P2** | N3（架构视图）、N5 其余（导出/工作区） | 提升深度与生产力 |
| **P2** | N6（质量与工程债，2.0 收口） | 为 2.1 多平台铺路 |
| **—** | **2.1 多平台支持** | 2.0 完成后启动 |
| **—** | **2.2 本地 Ollama AI** | 2.1 完成后启动 |

**建议 2.0 首个迭代聚焦 P0 + N2**：先让工具"能读更多语言、能读本地项目、能给出阅读顺序"——这三件事直接决定它是否好用。

## 7. 风险与开放问题

| 风险 | 说明 | 应对 |
|---|---|---|
| tree-sitter ABI 升级 | 0.25+ dylink 变更，旧语法包不兼容，可能牵动全部语言支持 | N6 提前做，成对升级 + 自检脚本 |
| 多语言解析质量 | 不同语言 AST 结构差异大，符号提取规则需逐语言适配 | 每语言独立单测 + fixture |
| 本地目录实时变更 | 文件夹打开后文件可能被外部修改 | 引入文件监听 + 手动刷新兜底 |
| 分析结果缓存失效 | 仓库更新后旧索引失效 | 按 commit/内容哈希版本化（沿用现有 cache 模式） |
| 规模提升带来内存压力 | 2000 文件全量 AST 驻留 | Worker 并行 + 按需解析 + 内存上限告警 |
| macOS 签名/公证 | 无 Apple 开发者账号则 Gatekeeper 拦截 | 2.1 先发未签名版 + 文档说明"右键打开" |
| 本地模型输出不可靠 / 显存占用 | Ollama 模型可能给出错误解释或占用大量内存 | 默认关闭 + 强标注"由本地模型生成" + 只做"先检索后解释"而非自由生成 + 可随时关闭 |

**已定调**

1. **版本编排**（2026-09-17）：多平台支持独立为 **2.1**；本地 AI 独立为 **2.2**。2.0 专注本地化 + 深度 + 体验。
2. **AI 边界**（2026-09-17）：坚持「**纯本地、无在线服务、无云端 AI**」红线不变；2.2 新增可选的本机 Ollama 集成——默认关闭、按需启用、断网可用、零外发。
3. **版本号统一**（2026-09-17）：全项目对齐 `1.0.0`。
4. **CI / 发布流程规范化**（2026-09-18）：文档站部署从 tag 发布中**解耦**（新增 `pages.yml`，跟随 `main` 部署，不再受 `github-pages` environment 的 tag 保护规则限制）；`release.yml` 只负责 tag → 构建 exe → 发布 Release；三个 workflow 统一最小权限；Dependabot 已忽略破坏性升级（`web-tree-sitter` / `tree-sitter-wasms` / React major）。流程约定见 [CONTRIBUTING.md](../CONTRIBUTING.md#分支与发布流程)。

**待确认**

- 2.0 的语言优先级：Rust / Go / Java / C / C++ / C# 中先做哪几个？（建议先 **Go + Rust**，与项目的 Tauri/Rust 背景契合且用户群重叠）
- 2.1 是否投入 macOS 签名与公证（需付费账号）？
- 2.1 与 2.2 的先后是否调整？（当前：多平台优先）
