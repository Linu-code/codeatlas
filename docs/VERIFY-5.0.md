## 必须说清的边界

1. **C4 的 80%~100% 不是"偶发 bug"**：当单个符号超过切片上限（1500 token）时会被截断，
   截断说明里会给出完整行范围。C4b 显示这种符号只占 0.5%~2.2%（p99 ≤ 2075），
   所以"自动扩展到整个函数"对 98% 以上的符号成立，**不是 100%**。
2. **C3 的成本随语言上升**：flask（1738）/ gin（1477）明显高于 JS 系（785~1165），
   因为它们的模块目录更深、文件更多，目录摘要更长。这是"分级"的固有成本，不是 bug。
3. **未覆盖**：5000 文件上限、超大仓库 tree 截断、AI 真实模型（本地无 key，仅 mock）、
   ZIP 内的符号链接/大小写冲突、非 UTF-8 编码。这些仍只有单元测试或完全没有验证。

## 本次核查顺带修正的错误

- 4.4 的「三仓库 890~1365 token」只在 3 个 JS/TS 仓库上测过；扩到 5 个仓库后真实区间是
  **785~1738**，已按实测更新 CHANGELOG 与 README。
- 4.3 写的 tsup「85% 完整覆盖」是小样本（10 个）的巧合；这次 10 个样本得 80%，
  两者都在"2 个超大函数被截断"的同一解释下，量级一致。

## 复现方式

```bash
# 1) 准备样本（任选 5 个仓库，解压到同一目录，每仓库一层子目录）
mkdir -p "$TEMP/carepos/extract"
# 目录名规则：owner_repo，例如 expressjs_express / vuejs_core

# 2) 跑核查
npx vitest run tests/unit/realRepos.test.ts --pool=threads
```
